Конспект: AbortController, Fetch и защита от гонок данных
1. Основы AbortController
Что это: Встроенный в браузер API для отмены асинхронных операций (в первую очередь fetch).

controller.signal — передается в fetch (в опции signal). Если вызвать controller.abort(), запрос прервется.

Отличие отмены от ошибки: При отмене fetch выбрасывает ошибку с именем 'AbortError'. Это не настоящая ошибка (пользователь просто передумал), её нужно игнорировать (не показывать красный экран).

Тайм-ауты и объединение сигналов:
AbortSignal.timeout(ms) — создает сигнал, который сработает автоматически через заданное время. Кидает TimeoutError.

AbortSignal.any([signal1, signal2]) — объединяет несколько сигналов. Запрос отменится, если сработает хотя бы один из них (например, таймаут или нажатие кнопки «Отмена»).

2. Как правильно проверять HTTP-статусы
Важно: fetch не выбрасывает ошибку на статусы 404 Not Found или 500 Internal Server Error. Он считает запрос успешным, если сервер вообще ответил.
Поэтому нужно всегда проверять response.ok:

javascript
if (!response.ok) throw new Error(`HTTP ${response.status}`);
3. Гонка запросов (Race Condition) и как её победить
Проблема: Пользователь вводит текст в поиске. Запрос на букву "a" уходит на сервер, затем на "ab", затем на "abc". Если сервер обработает "a" медленнее всех, результат для "a" придет последним и перезапишет правильный результат для "abc". Пользователь увидит не то, что искал.

❌ Плохой подход (без защиты):
Просто делаем fetch и рендерим. При быстром вводе результаты перемешаются.

✅ Хорошие подходы:
1. Отмена предыдущего запроса (AbortController):
Храним ссылку на активный контроллер. Перед каждым новым запросом делаем activeController.abort().

2. Проверка по счетчику (Request ID):
Если отмена не сработала (ответ уже летит), сравниваем myId с глобальным currentRequestId. Если они не равны — значит, это устаревший запрос, просто игнорируем его (return).

3. Комбинированный метод (Лучший):
Используем и AbortController (чтобы экономить трафик), и счетчик (чтобы защититься от микро-задержек при парсинге JSON).

4. Паттерн «Последний запрос побеждает» (Latest-Only)
Универсальный хелпер createLatestOnly(), который создает функцию-обертку. Она автоматически отменяет все предыдущие вызовы и возвращает результат только для самого последнего.

javascript
const latest = createLatestOnly();

// Если вызвать подряд loadUser(1), loadUser(2), loadUser(3), 
// то отрендерится только результат для 3-го пользователя.
5. Интеграция с React (хук useFetch)
Для React идеально подходит использование useReducer вместо useState.
Почему? useReducer не позволяет создать противоречивое состояние (например, loading = true и одновременно error != null). Состояния идут строго по цепочке: idle -> loading -> success или error.

Внутри useEffect создается AbortController.

В функции cleanup (return () => controller.abort()) запрос отменяется при размонтировании компонента (спасает от утечек памяти).

6. Дополнительные паттерны
Debounce + Abort:
Debounce ждет, пока пользователь перестанет печатать (например, 300 мс), и только потом шлет запрос. Если запрос уже ушел, а пользователь продолжил печатать — AbortController его отменяет.

Защита форм (Двойной клик):
Используем флаг isSubmitting. Если true — игнорируем клики. Кнопку блокируем (button.disabled = true).

Универсальный safeFetch:
Обертка, которая:

Поддерживает тайм-ауты.
Различает отмену пользователем (return { aborted: true }) и тайм-аут (кидает ошибку).
Бросает настоящие ошибки на 4xx/5xx.
Перехватывает сетевые сбои (TypeError) и выдает понятный текст.

Главный вывод: Никогда не доверяйте порядку ответов от fetch при быстрых действиях пользователя. Всегда используйте AbortController для отмены ненужных запросов, и проверяйте актуальность ответа перед тем, как обновлять UI.
